# 设计系统

创建 UI、调整视觉风格、实现响应式布局或修改主题敏感样式时读取本文件。

## 视觉方向

构建科技风个人开发者门户。

关键词：

- 科技感。
- 极简。
- 现代。
- 高级。
- 清晰。
- 快速。
- 开发者气质。

视觉效果要克制使用：

- 细腻渐变。
- 精细网格背景。
- 细线边框。
- 毛玻璃表面。
- 代码片段式面板。
- 数据可视化暗示。
- 轻量 hover 和进入动画。

避免：

- 装饰堆叠。
- 低对比度文本。
- 大面积重动画。
- 影响内容扫描的特效。
- 整站只有单一色系。

## 布局

优先保证：

- 首屏身份明确。
- 信息便于快速扫描。
- 页面层级清晰。
- 项目和技能信息密集但可读。
- 移动端可用。

常见页面模块：

- Hero：姓名、角色、简介和主要操作。
- 技能概览。
- 精选项目。
- 经历时间线。
- 博客或文章精选。
- 联系方式和社交链接。

## UI 控件

优先使用 Naive UI：

- 按钮。
- 菜单。
- 下拉。
- 标签页。
- 弹窗。
- 表单。
- 通知。
- tooltip。
- 数据展示。

使用 Tailwind 处理：

- 布局。
- 间距。
- 排版。
- 响应式。
- 简单过渡。

## 响应式设计

支持：

```text
320px+
768px+
1024px+
1440px+
```

移动端要求：

- 导航可清晰折叠。
- 触控目标足够大。
- 卡片和网格不溢出。
- 时间线保持可读。
- 主要操作保持可见。

桌面端要求：

- 内容宽度有约束。
- 宽屏下文本行长不过长。
- Hero 和项目区合理使用空间。

## 可访问性

使用：

- 语义化 landmarks。
- 描述清楚的按钮和链接。
- 可见焦点状态。
- 足够对比度。
- 表单控件 label。
- 有意义图片的替代文本。

不要只用颜色表达状态。

## 动效

动效用于强化交互反馈和信息层级。

推荐优先级：

1. CSS transition。
2. Vue transition。
3. 必要时使用 motion 类库。
4. 只有复杂动画确实值得引入依赖时才使用 GSAP。

动效不能阻碍阅读、滚动或操作。
